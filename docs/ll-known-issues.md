# lan-link 已知问题与改进建议

> 记录时间: 2026-06-03
> 场景: 全局 7 节点日志备份



## 已解决

### 1. 端口不统一 ✅（2026-06-03）

星狐儿的 `ExecStart` 已从 `--port 9877` 改为 `--port 9876`，systemd 已重载重启。


## 问题汇总

### 1. 端口不统一

| 节点 | 配置端口 | 实际端口 | 结果 |
|------|----------|----------|------|
| 团子 | 9876 | 9876 | ✅ |
| 星狐儿 | 9876 | **9877** | ❌ 超时 |
| 锐宿1号 | 9876 | 9876 | ✅ |
| 锐宿2号 | 9876 | 9876 | ✅ |
| 绿云1号 | 9876 | 9876 | ✅ |
| 绿云2号 | 9876 | 9876 | ✅ |
| 绿云3号 | 9876 | 9876 | ✅ |

**现象**: `Error: deadline has elapsed`，但 `ping 10.0.0.2` 正常、SSH 正常。

**原因**: 星狐儿的 lan-linkd 启动参数是 `--port 9877`，客户端默认连 9876。

**建议**: 
- 启动脚本/ systemd unit 统一用 9876
- 或客户端支持服务发现（UDP 广播探测）

### 2. exec 命令超时

**现象**: 
```
$ lan-linkctl exec "du -sh /var/log/*"
[exit 1]  # 或 timeout
```

**原因**: 
- 命令执行时间超过默认超时（约 10s）
- 大量输出时传输慢
- `info` 命令部分字段（内存）显示异常（单位 K 而非 G）

**建议**:
- exec 支持 `--timeout` 参数
- 大输出命令自动分片传输
- info 的内存单位修复

### 3. 文件传输不稳定

**现象**:
```
$ lan-linkctl pull -r /tmp/big-file.tar.gz -l local.tar.gz
Error: deadline has elapsed
```

**原因**:
- UDP 传输大文件（>100M）容易超时
- 没有断点续传
- 没有进度显示

**建议**:
- 大文件自动分块传输
- 支持进度条
- 支持断点续传
- 或内置 SSH/SCP 通道作为 fallback

### 4. 缺少批量操作优化

**现象**: 备份 7 个节点需要串行执行，总耗时 2+ 分钟。

**建议**:
- 支持并行连接多节点
- 支持 `--batch` 模式
- 或提供多节点管理脚本模板

### 5. 日志/输出格式

**现象**: 
```
$ lan-linkctl info
2026-06-03T02:24:21.977765Z  INFO lan_linkctl: Sent SYN...
Linux tuanzi...
---
Mem:
   total     used     free    avail
   15.3M     6.1M    1016K     9.2M   # 单位错误，应为 G
```

**建议**:
- 默认隐藏 INFO 日志（或用 `--verbose` 开启）
- 内存单位统一为 human-readable

## 改进优先级

| 优先级 | 问题 | 影响 |
|--------|------|------|
| P0 | 端口统一 | 连接失败 |
| P1 | exec 超时 | 命令不可用 |
| P1 | 大文件传输 | 备份/恢复失败 |
| P2 | 并行批量 | 效率低 |
| P2 | 输出格式 | 体验差 |
